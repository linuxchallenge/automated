# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Automated Indian stock/commodity/options trading system running on a Raspberry Pi. It trades across multiple broker accounts (Angel One, 5paisa, Zerodha, Upstox) with strategies for options straddles, commodity futures, index futures, cash equities, and Elliott Wave signals.

## Commands

### Run the main trading engine
```bash
python3 auto_straddle/AutoStraddle.py
# In production: sh autotrade.sh (infinite restart loop)
```

### Run tests
```bash
cd auto_straddle && python -m pytest tests/ -v
# Single test file:
python -m pytest tests/test_elliot_wave_signals.py -v
# Most tests are unit tests with mocks; some (test_zerodha_api, test_fivepaisa_order, test_upstox_order) require live broker credentials
```

### Run Elliott Wave backtest
```bash
cd elliot_backtest && python run_backtest.py
# Parameter optimization:
python optimize_params.py
# Walk-forward validation:
python walk_forward_validation.py
```

## Architecture

### Entry Point & Main Loop
`AutoStraddle.py` is the orchestrator. It logs into all broker accounts, then runs an infinite loop (~60s interval) executing each strategy within its time window (e.g., options 9:23–15:29, commodities during MCX hours, EW signals at 15:45). Each strategy call is wrapped in try/except with Telegram alerts on failure. A `SIGALRM` 5-minute watchdog kills hung strategies (Linux only).

### Broker Abstraction
`PlaceOrder.py` is the unified order adapter. Account names map to brokers: `deepti`→Angel One, `leelu`→5paisa, `avanthi`/`kite`→Zerodha. Each broker has its own sub-package (`angel_one/`, `fivepaisa/`, `zerodha/`, `upstox/`) with API wrapper and credentials file.

### Strategy Modules (all in `auto_straddle/`)
- `AutoStraddleStrategy.py` — ATM short straddle (NIFTY/BANKNIFTY)
- `FarSellStratergy.py` — Far OTM strangle
- `CommodityStratergy.py` — MCX commodity futures (Alligator indicator via TvDatafeed)
- `IndexFutureStratergy.py` — Index futures trend following
- `NiftyPositionalStrategy.py` — Weekly/positional NIFTY/SENSEX options
- `cash_stratergy.py` / `elliot_cash_stratergy.py` — Cash equity strategies
- `optionbuy_stratergy.py` — Option buying (currently disabled)

### Configuration
All dynamic config is loaded from Google Sheets (published CSV exports) via `configuration.py` (singleton `ConfigurationLoader`). Account lists per strategy are also Google Sheets. This allows live config changes without redeployment.

### Key Infrastructure
- `OptionChainData.py` — Live option chain from NSE India API (Groww fallback)
- `TelegramSend.py` — All alerts/notifications via Telegram Bot API
- `ledger_calculation.py` — Daily P&L ledger tracking across all accounts
- `fund_optimizer.py` — SEBI 50-50 margin split monitoring
- `commodity_data.py` — OHLCV data from TradingView via websocket
- `exchange_state.py` — Market open/holiday detection via Upstox API
- `logging_config.py` — File logging to `/tmp/auto_trade_YYYY-MM-DD.log` (on the Pi only; on this machine, log copies live in the repo root as `auto_trade_YYYY-MM-DD.log` — search those, not local `/tmp`)

### Elliott Wave Subsystem
The most complex component. Core algorithm in `elliot_wave_strategy.py` (swing detection → wave identification → Fibonacci validation → signal generation). Live signals generated by `elliot_wave_signals.py` at 15:45, synced to Google Sheets, executed by `elliot_cash_stratergy.py`. Standalone backtest framework in `elliot_backtest/` with validated 17% CAGR. See `elliot_backtest/HANDOFF.md` for full parameter docs and anti-lookahead rules.

### Data Flow at Runtime
Working directory is `~/temp/data_collection/` (set via `os.chdir()` at startup). Options chain CSVs, sold options tracking CSVs, ledger data, fund snapshots, and EW signal files all live under this directory. This directory exists only on the Pi — on this machine, ask the user to copy any needed CSV to a local folder. Instrument token maps are downloaded from broker APIs at login and cached to CSV with local fallback.

## Deployment

Deployed on Raspberry Pi via crontab (`crontab.txt`). `autotrade.sh` runs the main engine in an infinite loop with 1-minute sleep on crash. Separate cron jobs run `DailySchedule/`, `PortfolioReport/`, `IntradayIndexMovement/`, and `ip_address/` modules.

## Coding Agent Guidelines

### 1. Think Before Coding
- **Ask, don't assume:** If anything is unclear, ask before writing a line of code. Never make silent assumptions about intent, architecture, or requirements.
- **Surface confusion:** Do not guess. State if something is ambiguous and push back if a simpler approach exists.

### 2. Simplicity First
- **Minimum viable code:** Always implement the simplest thing that could work.
- **No over-engineering:** Do not add complex abstractions, boilerplate, or flexibility that weren't explicitly requested.

### 3. Surgical Changes
- **Touch only what you must:** If a file or function is not directly part of the current task, do not modify it.
- **No adjacent refactoring:** Do not "improve" adjacent code, comments, or formatting just because you are in the same file. Match existing style.

### 4. Goal-Driven Execution
- **Verify before declaring success:** Confirm the change works (run tests, check output) before saying you're done.
- **Stop and check:** Test your work strictly and make sure you aren't leaving loose ends.

## Key Conventions

- **Spelling convention:** Several files use "Stratergy" (not "Strategy") in their names — this is intentional legacy naming, do not rename.
- **Pylint suppression headers** at the top of every module are intentional.
- **No formal package setup** (no setup.py/pyproject.toml). Run directly with `python3`. Test `conftest.py` manages `sys.path`.
- **Time-gated execution:** Strategies check `datetime.now().time()` against specific windows. Market hours are Monday–Friday only.
- **NSEPriceCache:** Thread-safe TTL cache with rate limiting shared across cash strategies to avoid NSE rate limits.
- **Credential files** are gitignored and stored per-broker in their sub-packages.
